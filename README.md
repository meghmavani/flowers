# flowers

Flowers drawn in animated ASCII, with a different one each day.

**See today's flower:** https://meghmavani.github.io/flowers/

Each flower grows from a bud and blooms when the page opens. Click or press R to replay it.

## How the colours change

Colours are chosen per flower, from colours that flower really comes in. Some have a wide range (zinnias). Others stay within one family (mimosa, baby's breath).

A colour change only starts once everything on the page has opened, so it never interferes with the growth. In bouquets, one flower changes at a time, and it moves to whichever colour the bunch has least of. That's the behaviour the tulips already had. Lilies do the same, using only that lily's own colours.

Where a flower is made of many small parts, the new colour travels across it instead of arriving all at once, controlled by `WAVE` near the top of the page's script. For example, it climbs a delphinium spire and drifts across a hydrangea.

## How the daily flower works

`index.html` works out today's flower from the date and shows it, so there's no server or scheduled job.

1. Today's local calendar date becomes a whole number of days. It uses the date and not the clock, so daylight saving can't shift it.
2. Days are grouped into rounds as long as the list of flowers. Each round has its own shuffled order, generated from the round number, so everyone gets the same flower on the same date without any stored state.
3. Each flower appears once before any repeats. If a round would open with the flower that ended the last one, its first two flowers swap, so the same one never shows two days running.

The flower changes at the viewer's local midnight, so someone in Auckland reaches the next flower before someone in New York. A page left open moves on by itself, and a page that was asleep at midnight catches up when it's next visible.

## Adding a flower

1. Copy the page in `flowers/` that's closest to your flower, for example `flowers/zinnia.html` for a single-headed flower or `flowers/delphinium.html` for a spike, and give it a new name. Each page is self-contained.
2. Change the title, the shapes under `petal / leaf shapes`, `DEFS` and `PALETTE`. Draw anything that changes colour in white, and register it with `addPart`.
3. Add its name to the `pages` list near the top of the script in `index.html`.
4. Add it to the table above, then run the tests (below).
5. Commit and push. The site updates within a minute or two.

Adding a flower reshuffles the upcoming order. The rules above always hold within one version of the list, but on the day the list changes, the new order doesn't know what the old one showed yesterday, so that one day could repeat yesterday's flower.

## Running it locally

Open `index.html` in a browser, or open any page in `flowers/` directly. You need an internet connection because the pages load [PixiJS](https://pixijs.com/) from a CDN.

## Testing

There's nothing to install beyond [Node](https://nodejs.org/) and a browser.

**Rotation and page checks.** From the repo folder:

```
node --test
```

This runs the real script from `index.html`. It checks registration, repeats, month and year ends, time zones, daylight saving and midnight, along with each page's conventions and the lily palettes. It also runs every page's own easing and colour-mixing code frame by frame, to check that colour changes start and end without a jump and that no part of any flower changes colour faster than the rose does.

**Rendered pages.** The browser check has to be served over http:

```
python -m http.server 8123
```

Then open http://localhost:8123/tests/browser-check.html in the front window, and leave it there until it finishes. Chrome slows a window that doesn't have focus to about one frame a second. It loads every flower and measures its real frames for page errors, growth from bud to bloom, and colour change, both across the picture and within any one area of it. The sunflower is the control, as it has no colour change. For the lilies, it also checks each lily separately. Thumbnails of each flower appear at the end.

It also checks for sudden colour jumps, but only when frames arrive close together. If they don't, it reports "frames too slow to judge smoothness" rather than guessing. On a slow machine, add `?batch=1` to load one flower at a time, which takes about 10 minutes. Add `?only=rose,lilies` to check just those, or `&big` for larger thumbnails.
